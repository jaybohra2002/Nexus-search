# Learning Log & Architectural Decisions

*A chronological journal of every major concept and decision made in the Nexus-Search project.*

- Discussed the benefits of gRPC over JSON/REST for internal microservices. Binary serialization is faster and requires less memory.
- Chose `pnpm` workspaces over `npm` for the monorepo to leverage symlinks and prevent duplicate dependency downloads.
- Compiled `.proto` files into static TypeScript interfaces using `proto-loader-gen-types` to ensure strict typing and prevent production crashes.

## 2026-07-13: API Gateway Hardening (Phase 2A)
- Implemented a Global Error Handler to intercept errors and prevent stack trace leaks.
- Enforced a strict JSON response envelope (`{ success, requestId, data/error }`) for frontend consistency.
- Configured Request IDs automatically generated by Fastify for distributed tracing.
- Implemented graceful shutdown intercepting `SIGINT` and `SIGTERM` to allow in-flight connections to finish before killing the server.
- Read more: [api-gateway-hardening.md](file:///d:/Developer/nexus-search/docs/code-explanations/api-gateway-hardening.md)

## 2026-07-14: The Architecture Pivot (Domain-Driven Fastify & Ingestion First)
- **Fastify God File Anti-Pattern**: Realized that manually registering routes in `server.ts` is an anti-pattern for scaling. We are adopting Fastify's official enterprise standard: `fastify-autoload` and Domain-Driven folder structures (`src/modules/search`).
- **Ingestion vs Search Order**: Decided to build the Ingestion Service *before* the Search Service.
  - **Reasoning**: If we build Search first, the Typesense database is empty. We'd have to fake the data. By building Ingestion first, we process real Markdown files, use local Ollama to embed them, and populate Typesense. When we build Search, we get real, semantic results instantly.

## 2026-07-21: Domain Clean Architecture & LLM Theory
- **Layered Domain Architecture**: Separated concerns inside the Search module by creating dedicated `dtos/` and `integrations/` folders. Zod schemas now live as strict DTOs.
- **Node.js `util.promisify`**: Refactored the gRPC client to use Node's native `util.promisify` rather than manually wrapping callbacks in `new Promise(...)`. This is the senior engineering standard for bridging legacy callback APIs with modern `async/await`.
- **Zero Hallucination RAG**: Documented the architecture for achieving 0 hallucinations using Typesense Hybrid Search (BM25 + Vector via `nomic-embed-text`) and strict prompt context.
- **Chunking Strategies**: Documented the evolution of chunking (Fixed Size -> Sentence -> Recursive Character -> Semantic) and why we use Recursive chunking with overlap for production ingestion pipelines.
- Read more: [03-zero-hallucinations-rag.md](file:///d:/Developer/nexus-search/docs/distributed-systems/03-zero-hallucinations-rag.md), [04-chunking-strategies.md](file:///d:/Developer/nexus-search/docs/distributed-systems/04-chunking-strategies.md)

## 2026-07-21: API Versioning & Deep Directory Separation
- **API Versioning**: Refactored the Fastify Autoload pattern to use a `v1/` directory. All endpoints are now safely versioned under `/api/v1/`.
- **Deep Directory Tiering**: Completely wiped the flat domain modules and rebuilt them with strict categorical subfolders (`routes/`, `controllers/`, `services/`, `repositories/`, `integrations/`, `dtos/`).
- **Repositories vs Integrations**: Established the FAANG standard differentiation: `repositories/` are for internal, owned databases (Postgres, Redis). `integrations/` are for external boundaries (gRPC services, Stripe, Twilio).
- Read more: [03-api-versioning.md](file:///d:/Developer/nexus-search/docs/code-explanations/03-api-versioning.md)
